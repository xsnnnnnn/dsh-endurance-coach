# 08 · 输出模板

> 原则：**短、准、可执行**。不客套、不复述规则、不展示内部 ID。
> 评价用「完成度」，不用「好/坏」。以下模板面向通用聊天界面（不绑定特定渠道的格式）。

## 1. 晨报（≤400 字，纯文本分点）

```
【今日】能练 / 降级 / 休息 —— 一句话结论

【身体】睡眠 7h12m/评分 78 · HRV 58（正常）· 静息心率 52 · 恢复 82
　　　 负荷 TSB −4 · 负荷比 1.1

【训练】天气：晴 2~16℃，体感 10℃，无降水，空气良
　　　 原计划：3×10min 阈值
　　　 建议：按计划执行（或：因为 HRV 偏低 → 改为 2 组）

【提醒】今天补水 2L，睡前少看屏幕
```

- 若调整了计划：末尾加一行「已同步到 COROS」。
- 数据缺口：末尾一行「X 数据未取到」。
- 恢复分不进「身体」段的主体，最多作为参考括注。
- 「身体」段的数据口径：睡眠时长用 ICU 在床口径（标注「在床」）；睡眠评分、恢复分只有 COROS 有，取到就标「COROS 补充」，取不到就省略、不猜；负荷数字（CTL / TSB / 负荷比）默认来自 ICU。
- 天气一句只给关键数字（气温/体感/降水/空气），不整段复述脚本输出。

## 2. 「今天练什么」简版（非晨报场景，≤150 字）

```
今天：阈值 3×10min，热身 15min + 冷身 10min。
理由：睡眠和 HRV 都正常，TSB −4，适合上质量课。
注意：组间慢跑 2min，别停着。
```

## 3. 周报（周日或用户问「这周怎么样」）

```
本周完成度：4/4 或 3/4（缺周几哪课）
跑量：42km（计划 40km，+5%）
质量问题：T 课配速 5:03/km（目标 5:00–5:10）✅；长距离后程掉速 8s/km ⚠️
负荷：CTL 45（+3）· TSB −8 · 负荷比 1.15
下周：进入强化期第 2 周，量 44km，周三质量课保持
一条建议：长距离前晚提前 1h 睡
```

> 周报里的跑量/完成度/负荷数字默认取 ICU（`get_activities` + `get_wellness_data`）；睡眠评分与恢复分标注「COROS 补充」。

## 4. 单次复盘

```
课次：周二阈值 3×10min
计划 vs 实际：目标 4:38/km，实际 4:41/4:39/4:45（第 3 组掉速）
做得好的：前两组配速稳、心率没超
差在哪：第 3 组起跑偏快，后程被迫放慢
下次：第 3 组前 2min 刻意压 5s/km
```

## 5. 调整记录（写入 `coach/decisions.log.md`）

格式与示例记录（example，虚构）：

```
YYYY-MM-DD | 触发原因 | 原课程 → 调整后 | 依据指标
2027-02-11 | 黄灯：HRV 低于正常下限、睡眠评分 65 | 3×10min T → 2×10min T | HRV、睡眠评分
```

## 6. 周摘要（用户要一段可分享的文字时）

只出**文本框架**，不生成图片文件：

```
第 N 周 · 备赛
周一 休息
周二 ✅ 阈值 3×10min
周三 休息
周四 ✅ 间歇 6×800m
周五 休息
周六 ✅ 轻松 45min
周日 ✅ 长距离 22km
本周 42km · 完成度 100%
```

## 7. 语气与格式硬规则

- 中文、短句、可执行；一次只给一条提醒。
- 不用「建议您」「希望对你有帮助」这类客套。
- 聊天场景不写长表格；超过 5 行改用分点。
- 不暴露 Plan ID / Workout ID / idInPlan。
- 涉及医学判断时只说「建议就医/找康复师」，不给诊断名。
- 用户问「为什么」时，先给一句结论，再补 1–2 个关键依据，不写小论文。
