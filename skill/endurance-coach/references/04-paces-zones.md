# 04 · 配速 / 心率 / 功率 / 泳速分区

> 任何课表里出现数字目标前，先读本文件。**个人基准从 `coach/athlete.json` 读，本文件只是口径与算法。**
> 文中的数值均为 example（虚构示例），用来演示怎么从基准推出区间，不是你的真实数据。

## 3. VDOT 校准（每 4 周或出新成绩时）

```bash
python <this skill>/scripts/vdot.py --distance 5k --time 22:00
python <this skill>/scripts/vdot.py --distance 42195 --time 3:45:00 --json
python <this skill>/scripts/vdot.py --vdot 41
```

脚本用 Daniels & Gilbert 公式：

```
v   = 距离(m) / 时间(min)                         # m/min
VO2 = -4.60 + 0.182258·v + 0.000104·v²
pct = 0.8 + 0.1894393·e^(-0.012778·T) + 0.2989558·e^(-0.1932605·T)
VDOT = VO2 / pct
```

**示例（example，虚构）**：

| 来源 | 反推 VDOT | 说明 |
|---|---|---|
| 5k 22:00 | ≈ 44.5 | 当前速度能力 |
| 全马 3:45 | ≈ 41.0 | 当前耐力兑现能力 |
| 目标全马 3:45 | 需 ≈ 41.0 | 缺口在**有氧耐力兑现**：先补长距离与比赛配速 |

→ 若「短距离反推的 VDOT」明显高于「长距离反推的 VDOT」，说明速度尚可但耐力兑现不足，训练重点应放在长距离 + 比赛配速专项，而不是继续练 5k 速度。
→ 两套数字不要混着写进同一份课表。

## 4. 五区定义（Daniels）

| 区 | %VDOT(VO₂max) | 感觉 | 单次量 | 作用 |
|---|---|---|---|---|
| E 轻松 | 59–74% | 能说完整句子 | 30–150min | 有氧基础、恢复 |
| M 比赛配速 | 75–84% | 目标距离可维持 | 40–110min | 比赛专项 |
| T 阈值 | 83–88% | 「舒适地难受」 | 20–40min 累计 | 提阈值 |
| I 间歇 | 95–100% | 3–5min 可撑 | 每次 ≤5min，总 ≤8% 周量 | 提 VO₂max |
| R 重复 | 105–110% | 快而松 | 每次 ≤2min | 速度、跑姿经济性 |

**口径冲突处理**：档案里的阈值配速（来自 Intervals.icu / 设备评估 / 比赛成绩）与 Daniels T 配速常有 5–15s/km 差异。
→ 日常阈值课用档案阈值附近，并用 HRV/睡眠状态校准；状态 CAUTION 时退到 Daniels T。
→ 两套数字不要混着写进同一份课表。

## 5. 心率

- **跑步心率分区以档案里的数值为准**（现读，不硬编码）。
- 档案里没有心率分区数据时粗估：Z2 ≈ HRmax 的 65–75%。示例（example，HRmax 190）：**124–143 bpm**，E 跑封顶 143。
- 骑行按 Friel 五区（示例 LTHR 160）：Z1 <81%（<130）、Z2 81–89%（130–142）、Z3 90–93%（144–149）、Z4 94–99%（150–158）、Z5 ≥100%（≥160）。
- 心率是**滞后指标**：I 跑看配速达标，E 跑看心率封顶，T 跑两者都看。

## 6. 骑行功率七区（示例 FTP 200 W，example）

| 区 | %FTP | 功率 (W) | 用途 |
|---|---|---|---|
| Z1 恢复 | <55% | <110 | 恢复、通勤 |
| Z2 耐力 | 56–75% | 112–150 | **交叉训练默认区间** |
| Z3 节奏 | 76–90% | 152–180 | 甜点区下沿 |
| Z4 阈值 | 91–105% | 182–210 | 阈值课 |
| Z5 VO₂max | 106–120% | 212–240 | 3–8min 间歇 |
| Z6 无氧 | 121–150% | 242–300 | 30s–2min |
| Z7 神经 | >150% | >300 | 冲刺 |

> 交叉训练只排 Z2（示例 112–150 W），单次 ≤90min。要骑行专项时才动 Z4 以上。
> 换了自己的 FTP 后，整张表按 `FTP × %` 重算，不要沿用示例瓦数。

### FTP 校准（CP20 测试）

流程：热身 20min → 3×1min 开脚（不全力）→ 恢复 5min → **20min 全力** → 放松 15min。

```
FTP ≈ 20min 平均功率 × 0.95
```

- 测完让用户把 20 分钟平均功率发来，再算 FTP。
- 默认阈值参考 Intervals.icu 的 eFTP 与功率曲线；两者与 CP20 结果不一致时，以最近的 CP20 测试为准（并在档案 note 里写明来源）。
- **改任何平台/档案里的 FTP 前必须先征得用户同意**，不要自动写。
- 更新后刷新 `coach/athlete.json` 的 `cycling` 字段，并重算本文档的功率七区。
- 建议每 6–8 周复测一次；测前 48h 不做高强度骑行。

## 7. 游泳（需用户提供数据）

- **CSS（临界泳速）**：`CSS = (400m 时间 − 200m 时间) / 2`，得到每 100m 配速。
- **CSS 分区**：恢复 = CSS+15s/100m；耐力 = CSS+8~10s；阈值 = CSS±2s；VO₂ = CSS−5s。
- **SWOLF** = 单程时间(s) + 划水次数，越低越好，**只和自己的历史比**。
- **游量**：按周/月统计距离、时长、次数；铁三备赛期建议每周 2 次、单次 1500–2500m。
- 无池长/测试数据时：只讲方法与课型，**不编配速**。
